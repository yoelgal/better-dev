# The ask corpus. One line per ask, in the words a busy senior developer types. run.sh draws one line
# per fixture with the system RNG and sends it as that fixture's last ask, so two runs probe different
# work rather than the same four hardcoded jobs. Comment lines and blanks are never drawn.
#
# Rules for a line you add:
#   - it is a user's ask, never a better-dev word: no skill name, no phase, no "contract", no "loop".
#     The persona speaks it verbatim, and a persona that names a skill has coached the agent.
#   - it names no stack. A line that says "npm" only works in one fixture; a line that says "the test
#     suite" works in all four, and lands in a repo that has none - which is the interesting case.
#   - it is one sentence, lowercase, no trailing period. It should read like it was typed in a hurry.
#   - it is a distinct ask class, not a rephrasing of a line already here. The corpus buys coverage of
#     what an ask routes to; a synonym buys nothing and dilutes every draw.
#   - append it at the END. run.sh pins a draw by position among the drawable lines, so inserting one
#     mid-file silently repoints every --ask a past run recorded.
