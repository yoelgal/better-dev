# Releases

Machine-read by the session-start hook and `/update`. One line per release, newest first:
`<version> <flags> - <summary>`, where `<flags>` is a comma-joined subset of
`install,reonboard,offer`. Four tiers: **pull-only** (the default - `git pull` in the clone is the
whole update), **install** (a skill dir was added, removed, or renamed - re-run `install.sh` once
per machine), **reonboard** (a repo surface changed - re-run `/onboard` once per wired repo), and
**offer** (the release added something opt-in - ask the operator once whether they want it). A
version with no line here is pull-only; flags are never empty. One line covers everything in its
release, so its flags are the **union** of what each change in it needs, never the mildest one: a
release that changed a repo surface *and* removed a skill dir is `install,reonboard`, because
dropping the `install` tier leaves a dangling link to a deleted skill on every machine and no nudge
ever fires for it. A line that removes or renames a skill also names where its job went - the skill
that absorbed it, or "retired, nothing replaces it" - since the installer prunes the link silently
and the operator's next question is what to reach for instead.

The first three tiers say *do this to stay current*; `offer` is the only one that asks a question,
and it exists because a new capability otherwise reaches new installs alone. A first install meets
an opt-in capability at its own front door (`BOOTSTRAP.md`); an already-wired machine never runs
that again, so without this flag the capability ships invisible to every existing user. `/update`
collects pending `offer` flags exactly like the other two and puts each summary to the operator as
a one-time question; the `wired-version` stamp closes it, so a declined offer is not re-asked.

**An `offer` line always carries `reonboard` too.** Only the reonboard nudge fires from
`bd-session-start`, so an offer without it is an offer nobody is ever prompted to collect. The
package gate enforces the pairing.

0.11.0 install,reonboard - the front door delivers what it promised. **The clone install now registers the awareness hooks**, through the new `scripts/bd-hook-wire`, into each host's verified machine-global hook config (`bd_host_hook_settings` in `hosts/<name>`; codex and hermes decline explicitly and say so). Until now only the plugin channel wired them - and since an agent told "install better-dev" reads BOOTSTRAP and cannot drive an interactive plugin installer, it always took the clone path, so the common install shipped **no session hook in any repo** while BOOTSTRAP claimed the tool installs hooks. `install.sh --verify` now fails on skills-linked-but-hooks-absent, and the package gate enforces channel parity so the two hook sets cannot drift again. **Parked decisions stop evaporating**: a greenfield `/onboard` defers the merge-policy question because the repo has no PR to merge yet, and nothing ever collected it - so the repo silently carried a policy nobody chose. `/guardrails-install` now writes the parked record instead of intending to, `/plan-grill`'s contract seal is named as its collector and asks the question there, `/groundwork` re-runs `/guardrails-install` once the foundation lands a stack, and the session note reports any parked decision still waiting. **The carve gate renders before it asks**: `/groundwork` step 5 splits into two turns - table first, question second - because one turn reliably collapsed into the question prompt and collected approval for a list the user never saw. **New: draw it when the answer is a shape** (`wait-what`'s `visuals.md`) - a component's role, a boundary, an order of events, reached from `/wait-what` and mid-grill in `/plan-grill` and `/groundwork`. **A promote now leaves you on the integration branch**, not the release branch: `/release-promotion` switches back and pulls right after the tag push, so a session no longer ends on `main` holding a stale local `staging` ref - and the rollback and back-merge steps, which had been reaching the release branch by position, now switch explicitly. Re-run install.sh once per machine to register the hooks (this is the whole point of the release), then /onboard per wired repo.

Also **D31**, an attribution reversal decided mid-release: for an MIT-licensed skill source this library now keeps the author's wording where the wording carries the value and credits it in NOTICE by file rather than by sentence - eight review rounds established that paraphrasing a well-made line to avoid an attribution line is the wrong trade. No skill behavior changed for it. Re-run install.sh once per machine so /wait-what links, then /onboard per wired repo for the two new routing rows.
